# Mana Station website

A static site: plain HTML, one stylesheet, a little JavaScript. No framework.

## Pages

| Page | For | What it does |
|---|---|---|
| `index.html` | Everyone | What the station is, the three ways in, how it works, prices. Shows the playground station's live Mana. |
| `get.html` | Wallets and app builders | **For my wallet:** buy a daily Mana pass. **For my app:** upload an app with a ticket, then buy an app plan. **Your Mana:** everything the wallet holds, with refunds; renew or cancel. |
| `play.html` | Players | Tap as a brand-new player with no KOIN; the station pays. |
| `owner.html` | Owner and council (not indexed) | Give your own apps free Mana in sizes, change or remove it; see customers; pause; council votes. |
| `help.html` | Everyone | Plain-language guide and questions. |

Every page shares the same header with a **wallet chip** (top right): pick a test wallet kept in this browser, or Kondor, once, and every page uses it.

## Files

- `src/*.html`: page sources. **Edit these**, then run `node site/tools/build-pages.mjs`, which fills in the shared header, wallet chip and footer (`src/parts/`) and writes `site/*.html`.
- `ms.js`: shared code: network, the chosen wallet, sending (the station pays when its rules allow, otherwise the wallet's own Mana), plain-language errors.
- `wallets.js`: test wallets in this browser's storage (testnet only).
- `abis.js`, `playground.js`, `app-code.js`: generated by `node site/tools/make-site-data.mjs` from the contract ABIs, `testnet/playground.json` and the demo app build.
- `styles.css`: all styling; tokens at the top, light and dark themes.

**See it locally:** open `index.html` in a browser, or run `npx serve site` from the repo root.

**Publish:** any static host works (GitHub Pages, Cloudflare Pages, Netlify). Point it at this `site/` folder.

**Before mainnet:**
1. Point `playground.js` at the mainnet station and stablecoins, and drop the testnet bar in `src/parts/top.html`.
2. Raise the size presets in `src/get.html` (they're at playground scale).
3. Add `<link rel="canonical">`, `og:url` and an `og:image`; fill in the domain in `sitemap.xml` and `robots.txt`.

## Search and sharing (built automatically)
`node site/tools/build-pages.mjs` writes, for every page, the canonical address, Open Graph and Twitter cards
(`og-image.png`), structured data (breadcrumbs; FAQ from the `<details>` after a `data-faq` marker; site, app and
prices on Home), plus `sitemap.xml`, `robots.txt` and `site.webmanifest`. The public address lives in one place,
`site/tools/site.config.mjs` (`SITE`): change it when the domain is ready, rebuild and republish.
After the first publish, add the site in Google Search Console and Bing Webmaster Tools and submit `sitemap.xml`.
